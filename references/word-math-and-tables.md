## 1. 什么必须写成公式对象

以下内容即使出现在普通句子或表格中，也必须是可编辑OMML：

- 单个数学变量，如 rho、mu、theta、d、M；
- 带上下标变量，如 `P_r`、`P_EH`、`R_ub`、`C_V,max`、`I_high`；
- 向量、矩阵、集合、期望、概率、运算符和约束；
- 数学意义上的BER、SNR、PTE等量；
- 表头和参数列中的变量。

以下内容通常保留为普通文字：

- 作为方法或软件名称的SWIPT、PSO、MATLAB、IEEE、AWGN；
- 普通英文句子和文献题名；
- SI单位，例如mW、kHz、A；
- 单位中的微前缀，例如μW、μH、μF。

判断原则：若它需要斜体、上下标、运算关系或在公式中代表一个量，就使用OMML；若它是名称、缩写或单位，就使用普通文字。

## 2. OMML实现

### 2.1 对象类型

- 行内变量：在正文段落或单元格中插入 `<m:oMath>`。
- 独立公式：使用 `<m:oMathPara>`，或在独立公式段落中放置 `<m:oMath>`。
- 不得把LaTeX字符串、Unicode下标字符、公式截图或普通斜体文本当成数学对象。

### 2.2 推荐转换链

优先构造MathML，再通过Microsoft Office的 `MML2OMML.XSL` 转成OMML。常见Windows Office路径为：

```text
C:\Program Files\Microsoft Office\root\Office16\MML2OMML.XSL
```

实际执行前应搜索本机Office目录，不要假定固定版本。可导入 `scripts/omml_helpers.py`：

```python
from omml_helpers import mathml_to_omml, simple_identifier_mathml

mathml = simple_identifier_mathml("P", sub="EH")
omml = mathml_to_omml(mathml, inline=True)
paragraph._p.append(omml)
```

复杂公式应直接生成完整MathML，不要用简单字符串替换器猜测语义。

### 2.3 字体与行高

数学字体使用Cambria Math。正文行内公式的视觉字号应与正文协调，通常为10.5–12 pt；表格公式与表格文字一致。

不要依靠过大的数学字号撑高固定20 pt正文行。独立分式、根式和矩阵必须检查是否被固定行高裁切；必要时仅对独立公式段落使用更合适的自动或固定行高。

## 3. 公式编号与引用

公式编号使用Word字段，不手工输入：

```text
(章节号-SEQ Equation)
```

章内第一式使用 `SEQ Equation \r 1`，后续使用 `SEQ Equation \n`。为号码建立 `eq_<章>_<序号>` 书签，正文用 `REF eq_<章>_<序号> \h` 引用。

更新流程：在Word中全选，按F9，再重新分页和保存。

## 4. 标准三线表

### 4.1 线条

标准三线表只保留：

- 表格顶线：黑色实线，建议1–1.5 pt；
- 表头下分隔线：黑色实线，建议0.5–0.75 pt；
- 表格底线：黑色实线，建议1–1.5 pt。

必须去除：

- 左右外边线；
- 所有竖线；
- 表体内部横线；
- 灰色网格、彩色表头、渐变和单元格底色。

### 4.2 几何与排版

- 明确设置 `tblW`、`tblGrid` 和每个 `tcW`，使列宽一致；
- 按内容分配列宽，不使用无意义等宽列；
- 表头重复，单元格垂直居中；
- 行高设为自动，不使用可能裁切文字的固定高度；
- 短数值居中，长说明左对齐；
- 变量使用OMML，单位直立；
- 表题置于表上方并与表保持紧密，但不能粘连。

### 4.3 压缩顺序

表格超宽或导致分页时依次处理：

1. 删除重复说明列；
2. 调整列宽和换行；
3. 缩写表头并在题注解释；
4. 调整单元格边距；
5. 在模板允许范围内小幅缩小表格字号。

不得用彩色Excel样式、全网格或极小字号解决论文表格问题。

## 5. 审计规则

严格审计至少检查：

- 存在OMML节点；
- 无 `\\frac`、`\\rho`、`\\mu` 等残留LaTeX；
- 无 `P_r`、`R_ub` 等普通文本下标；
- REF字段目标书签全部存在；
- 表格没有底色和竖向/内部边框；
- 表头下分隔线存在；
- 数学对象和独立公式数量与文稿规模相符。
