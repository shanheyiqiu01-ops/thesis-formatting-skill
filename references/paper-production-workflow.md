## 1. 任务建档

开始前记录以下项目：

- 正式输出路径、文件名和版本号；
- 官方模板是否存在，以及官方模板的优先级；
- 目标篇幅、语言、单栏/双栏、首页结构和参考文献格式；
- 允许读取和修改的代码、数据、图件与历史文稿；
- 是否允许重新运行程序、修改图件、搜索文献、提交Git或迁移目录；
- 工作树中已有的未提交修改。

先保留文件清单和Git状态。编辑任务只修改授权范围，不回退用户已有改动。

## 2. 证据与主张边界

建立一个内部证据矩阵：

| 主张类型 | 可接受依据 | 写作边界 |
|---|---|---|
| 系统模型 | 源码、公式说明、配置文件 | 明确理想化和近似条件 |
| 定量结果 | 当前版本CSV/JSON/MAT或实测记录 | 不从旧稿复制历史数字 |
| 方法优势 | 同条件基线比较 | 写明比较对象、指标与工况 |
| 文献事实 | 已核验出版物 | 不生成无法验证的题录 |
| 工程性能 | 电路、有限元或硬件实测 | 纯解析仿真不得写成实测 |

若目标是会议短文，优先形成最小闭环：问题、模型、方法、基线、结果、局限。不要用额外复杂度替代证据。

## 3. 论文框架

通用方法型论文可使用：

1. 摘要与关键词；
2. 引言：背景、文献脉络、缺口、贡献；
3. 系统/问题模型：架构、假设、公式和性能指标；
4. 方法：变量、目标、约束、求解器和复杂度/核验；
5. 结果与讨论：设置、基线、敏感性、主结果、鲁棒性和局限；
6. 结论、致谢、参考文献。

每个贡献必须在正文中有对应公式或实验，在结果中有对应图表，在结论中只总结已经验证的内容。

每张结果图按六个要素解释：

1. 坐标、单位、扫描对象和图例；
2. 使用的公式、数据和固定设置；
3. 主要趋势及物理/算法原因；
4. 同条件的方法比较和定量差异；
5. 图能直接支持的结论；
6. 参数范围、模型假设和不可外推边界。

## 4. Word生产

### 4.1 样式先行

先设置页面、正文、标题、题注、表格、参考文献和公式样式，再写正文。不要依赖Word默认样式或逐段临时格式。

无正式模板时采用本技能的A4中文学术规范；有正式模板时只补足其缺失的数学对象、编号和交叉引用能力。

### 4.2 数学对象

正文中的变量、表头变量、公式和约束全部使用OMML。详细规则见 `word-math-and-tables.md`。

独立公式使用可编辑数学对象，并用 `SEQ Equation`、书签和 `REF` 实现编号与引用。不得用图片、普通LaTeX文本或手工号码替代。

### 4.3 表格

学术参数表和结果表采用无颜色三线表。变量单元格使用OMML；数值和单位保持一致；列宽按内容分配；表头可重复；行高自动。

### 4.4 图件

优先使用已核验的高分辨率PNG或目标模板支持的矢量图。保持纵横比，不裁掉坐标、图例和注释。Word不能修复图内字体，源图不合格时回到绘图程序修改。

### 4.5 字段

图、表、公式和参考文献编号使用SEQ字段，正文引用使用REF字段。每次大改后在Word中执行全选和F9更新，再重新分页。

## 5. 分页与版式修订

先用Word实际分页确定问题位置，不以python-docx估算页数冒充Word分页。

遇到空白或孤行时依次处理：

1. 检查题注与对象是否错放；
2. 检查表格是否属于错误小节；
3. 检查 `keepWithNext`、分页符和段前分页；
4. 删除重复说明或无信息增量的列；
5. 适度调整图片、表格、题注、独立公式和参考文献间距；
6. 最后才考虑模板允许范围内的字号或边距变化。

若真实OMML使稿件比普通文本版本多一页，不得把公式退回普通文本。应保留正确格式并如实报告页数，等待正式会议模板重排。

## 6. 验收

### 6.1 结构验收

运行：

```powershell
python scripts/audit_academic_docx.py "paper.docx" --strict
```

至少确认：

- DOCX包可读取；
- 存在真正的 `m:oMath`/`m:oMathPara`；
- 无残留LaTeX命令和普通文本下标；
- 图、表、公式和文献的SEQ字段存在；
- REF目标书签存在且名称唯一；
- 三线表无底色、无竖线和内部网格；
- 图片关系和数量合理；
- 没有临时锁文件、示例占位或未授权栏目。

### 6.2 Word验收

使用Microsoft Word更新字段并重新分页。检查页数、表格跨页、题注位置、公式断行、孤行和对象重叠。

### 6.3 视觉验收

按照 `documents` 技能渲染PDF和逐页PNG并逐页查看。若LibreOffice缺失，可使用Word导出通道；若仍无法形成页面预览，只能声称完成结构审计和Word分页，不能声称完成逐页视觉验收。

## 7. 交付与迁移

交付目录只保留用户要求的正式文件。删除临时PDF、渲染页、缓存、锁文件、构建脚本和无用途备份。

若用户要求移动整个论文项目：

1. 列出源目录和目标目录；
2. 比较目标是否已有旧副本或独有文件；
3. 复制源目录到临时暂存目录；
4. 比较相对目录、文件数量、大小和逐文件SHA-256；
5. 运行项目自带验证脚本；
6. 原子切换到目标目录；
7. 再次校验；
8. 仅在用户明确要求后删除旧目录；
9. 检查新位置的Git状态和最终交付文件哈希。
